Boot from Android
-----------------
Keep the matching system-sileo.apfs at the local path above. Never publish
either system image. Use --system for Sileo; omit it for the original fallback.
Run from this project directory, using the connected phone's serial:

/opt/homebrew/bin/python3 tools/boot-op13-gles-v3.py --payload experimental/screen-brightness/control-v2/payload.bin --system experimental/sileo/v1/system-sileo.apfs --serial YOUR_SERIAL --output diagnostics/ios-gles-next

Use a NEW diagnostics output directory each time. The helper checks payload,
kernel, current turtle UEFI and system hashes, verifies Android platform sun,
uses fastboot boot, stages payload/system into RAM, prepares slider/touch,
enables the screen configuration clock, starts iOS and saves three live log captures. It leaves iOS running.
It never flashes or erases partitions. Cold reset before another GPU session:
the GPU retains protected memory and cannot safely return to a reused loader.
With v13 loaded, return to Android from live seven-core iOS with:

fastboot -s xnuloader reboot

This was tested: Android completed startup in about 23 seconds. A physical
restart is only needed if USB/firmware itself is unresponsive. Do not use oem
stop to reuse GPU memory. Ordinary reset is separate from touch cleanup.

Read-only package check without contacting the phone:
/opt/homebrew/bin/python3 tools/boot-op13-gles-v3.py --payload experimental/screen-brightness/control-v2/payload.bin --system experimental/sileo/v1/system-sileo.apfs --check

Live diagnostics during this seven-core GLES session:
fastboot -s xnuloader getvar result
fastboot -s xnuloader oem log
fastboot -s xnuloader get_staged ios-live.log

Linux / Windows is a DIFFERENT second UEFI
-----------------------------------------
experimental/multiboot/linux-windows-v1/dodge-uefi.img

Do not use that image for the iOS staging sequence. It is a separate EFI
manager for supplied ARM64 FAT boot media. Actual Linux/Windows OS boots
are not yet verified. Its instructions are in:
experimental/multiboot/linux-windows-v1/README.txt

If that manager is idle, fastboot -s xnuloader reboot returns to Android;
then follow the iOS instructions above. If an OS has taken over, physically
restart instead. The second image does not replace the current iOS UEFI.

UEFI source/build notes: experimental/uefi-turtle/README.txt

Optional live-USB iOS profile (verified 2026-10-26)
------------------------------------------------
Use the dedicated seven-core profile to retain USB diagnostics during iOS:

/opt/homebrew/bin/python3 tools/boot-op13-live-usb.py --serial YOUR_SERIAL --payload experimental/usb-live/seven-core-v1/payload.bin --output diagnostics/usb-next

CPU0 remains in firmware; iOS runs on seven cores. Live log downloads and
physical USB reconnection were verified while iOS stayed running. Touch and
battery were confirmed by the user. This is firmware fastboot access, not an
iOS SSH/file shell. The normal eight-core payload remains available.

Read live logs:
fastboot -s xnuloader getvar result
fastboot -s xnuloader oem log
fastboot -s xnuloader get_staged ios-live.log

Source-only checkout: recreate the local payload with
 tools/make-op13-live-usb-payload.py and your locally built matching kernel.
